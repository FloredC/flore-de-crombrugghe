Figma → code sync

Two days of building the portfolio straight out of the Figma file: four NDA subpages, a prev/next component that went through five shapes, and a long refinement loop on cards and illustrations. Mostly a log of what made that loop fast or slow — the product decisions are here, but the reusable material is about how the design file has to be structured for someone else to build from it.

27 Aug 2026 New pages: the NDA tier, the island page, and killing the card buttons Building with Claude

Started by asking for a read on the Figma NDA section before building anything — which turned out to be the right order, because the review found four content bugs and a structural blocker that would each have cost a round-trip if they'd been discovered mid-build. Then built the pages, and in the process removed every CTA button from the homepage cards.

Reviewing before building paid for itself

The four NDA frames had been duplicated from PitchPivot, and the duplication left fingerprints: every body text layer was still named "PitchPivot helps designers translate design thinki…". That's cosmetic, but it's the tell that explained the real errors riding along with it.

Pre-build review
Read the whole Figma section and report problems before writing any code
Found: SAC's eyebrow was myRIDE's copy; myRIDE and SAC both credited "Ubique for SBB"; SBB's image layer was named trail-app-thumbnail.png; duplicate NavbarDesktop instances on all four frames; an orphan empty container 3,000px below each frame's bottom. Two of these were real, publishable content errors on a client's project.
Correction
Fixed SAC's credit line in code against the frame — 2022 … Ubique for SAC, not 2024 … Ubique for SBB
The frame contradicted itself: its own Scale line said 2022, and the client is the Swiss Alpine Club. Shipping a wrong client attribution on a real client's project isn't a divergence worth deferring. Flagged rather than silently applied.
Blocker
The route actively refused to render NDA projects
ProjectPage redirected every nda-project to /, because before this they had no page to go to. Replaced with a narrower guard: redirect only if an NDA project has no case-study module.

The card CTA question shipped

Flore wanted to delete the CTA buttons from the project cards and rely on the cards themselves, and asked whether the usual objection ("you always need a button, especially on mobile") held.

It didn't, and the reason was measurable: every card was already a single anchor with a stretched ::after covering the whole article. The tap target was the entire 769×702 card and always had been — the pill was a label on a target, not the target. Removing it changed the hit area by nothing.

27 Aug
Move the link onto the card title instead of deleting the anchor
The anchor's text is its accessible name. Ten cards used to announce as ten links all called "Read case study" / "View Project"; they now announce by project. Removing the button was a net accessibility gain, not a break-even — but only because the anchor moved rather than disappearing.
27 Aug
No underline on the title link
Flore, explicitly. The affordance is the site's existing action-link colour step plus the media frame's hover lift — both already built, neither needing an underline. Underline stays reserved for the navbar's current-section mark.
27 Aug
Split LINK_COLOR_CLASS out of LINK_CLASS
LINK_CLASS carries font-bold; applying it whole would have silently restyled every card title. Same states, one definition, no drift.

"Island", not "city"

Building the Welcome to my city page surfaced a naming split: the Figma frame, the page title and the asset folder all said island, while the slug, the route, the homepage card and the whole map concept said city. Flagged rather than reconciled, because it's a naming decision. Flore chose island.

The rename went past the project: the homepage greeting bubble and the og:image:alt both carried the old metaphor. The tell that it was a concept rename rather than a page rename was in Flore's own hero screenshot — the asset already read "Hi, thanks for visiting my island" while the live site still said city. The old URL redirects rather than 404s, since it had been live and shareable.

Two things worth remembering about the assets

Baked-in chrome

The NDA hero exports had the NDA stamp burned into the artwork, where everywhere else on the site it's a live Badge component. That means it can't be reused, it scales down with the image on a phone, and it's a picture of a component that can drift from the component.

Format drift

Delivered as PNG (up to 597KB) where every other asset on the site is WebP. Converted on the way in — 1.3MB down to 315KB. Also renamed hero-sac → hero-trail-app, since SAC is the client and trail-app is the slug.

28 Aug 2026 The refinement loop: pagination, card media, illustrations Building with Claude

A long back-and-forth: Flore edits a component in Figma, I adapt, she looks at it on her laptop and phone, repeat. Productive, but this is the session where the cost of how the Figma file is structured showed up most clearly — three of the four slowest moments were file-structure problems, not code problems.

28 Aug
Read "filler" as intent, not as a component to reproduce
Flore added a filler node in Figma so the two sides would align regardless of title length. I built it literally: an explicit spacer element and a 200px floor on the mobile row, because the frame drew both. On her phone that left ~63px of dead air in the middle of the band.
"I added fillers to be sure that everything would be aligned but you took it too literal… Don't add unnecessary space." — Flore, after seeing v5 on her phone

The correct read was structural and had no spacer in it: give each column exactly two children — a text group and the thumbnail — and let justify-between pin one to the top and the other to the bottom. The row stretches both columns to the taller one's height, so the shorter column simply gets more space in the middle. Nothing is added; the leftover is absorbed where there's nothing to misalign.

The general lesson: a filler, a spacer, a fixed row height — these are how a designer expresses "these should line up" inside Figma's box model. They're a description of the goal, not a spec for the DOM. The mobile row's 200px and the desktop row's 255.666 were both sized around multi-line test strings in the frame (jfd;ljfkdjfal;djafkldj…), so reproducing them faithfully imported placeholder text as a layout constant.

Where the Figma file cost the most time

Slowest moment
A button instance living in a page frame I wasn't reading
The GitHub button (5022:9636) is a child of 4897:4623 — a section in a different Artifakt page frame from the one I'd inspected. I searched that frame's hero and all eleven sections; it genuinely wasn't there. get_metadata on a node returns x=171, y=912 but never names the parent, and 171 is the left margin on every section, so I inferred the hero. Cost: two wrong placements.
Fix
Send the containing node id, not the component's
One call and it's unambiguous. A component id says what a thing looks like; only the parent says where it goes. Worth doing by default when a new element is being placed rather than restyled.
Also costly
Chrome baked into illustration assets
The four principles SVGs contained the rounded border as a #D2D2D2 path inside the artwork. So the frame couldn't be resized — scaling a 278×262 asset into a 278×200 box would have shrunk its own border and left a 212-wide rounded rectangle floating inside a 278-wide card. Had to strip the border path from all four files and move the frame into CSS.
Repeat offender
Copy-paste drift between duplicated frames
Same root cause as the NDA frames the day before. Layer names are the cheapest tell: if a frame's text layers are still named after the frame they were duplicated from, assume the copy needs checking too.

The small cards: a constraint that wasn't a CSS problem

Flore wanted the three Feature-case cards "more rectangular than square" and aligned as a row. The alignment was solvable; the shape wasn't, at first, and the reason was in the assets:

Card sizeAssetRatio
large (Artifakt)1760×9101.93
medium (6 cards)1062×6311.68
small (3 cards)1280×11121.15

Because the artwork sits contained on the tint rather than cropped to the panel, its own height set the panel's floor. A landscape panel could only be bought by shrinking the artwork — which Flore had already rejected on the 25th as "very small and hard to see". The two goals were genuinely incompatible at that asset ratio.

28 Aug
Stop hardcoding the crop; derive the artwork box from the panel
IMAGE_ASPECT.small was a fixed 3/2 that every other number had to be arranged around — and it silently overrode whatever ratio Flore exported. Making the artwork flex-1 means it takes whatever height is left after the caption and padding, so changing the caption or the padding moves the artwork automatically.
28 Aug
Keep 3/2 as a floor, not a size
On a flex item, min-height: auto resolves to the intrinsic size, and an aspect-ratio is what supplies that. So a long caption grows the panel instead of quietly eating the image. (This also means min-h-0 — the usual companion to flex-1 — must not be set, or the floor collapses.)
28 Aug
Subgrid for the 3-up row
"The height of the small cards group should adapt to the longest text." Reserving two caption lines only covers the current content. Subgrid makes it dynamic: forcing a third line onto one caption takes all three panels 255 → 275 together, verified in the browser.
28 Aug
object-top instead of centre
The crop amount is arithmetic and can't be argued with — a 1.2 source in a 1.48 box loses 18.8% of its height. But the default centre position was splitting that loss between top and bottom, taking ~22px off each end. The top is where these images carry what identifies them. Same crop, better crop, costs nothing.

Technical traps worth not re-learning

TrapSymptomFix
getBBox() on an <svg> root Returned inks ~1.6× too large once a viewBox was set. I built the principles' shared canvas around those numbers and the drawings came out small and floating. Measure the <path>, not the root. The corrected union then landed on exactly (100, 65) — the centre of a 200×130 box, which is what Flore's component already used.
Tailwind class interpolation group-hover:${SHADOW} compiles to nothing. The hover shadow would have silently never painted. Tailwind scans source text for complete literals and never evaluates the file. Every variant written out in full, with a comment saying why the repetition stays.
box-sizing: border-box min-h-[200px] on a padded row produced a 137px row. min-height includes the padding. Write the total (264 = 200 + 32 + 32).
object-fit default The ValueCard images had a declared aspect ratio and no object-fit — so they'd been silently stretching, because the browser default is fill, not contain. Always state it when a box's ratio can differ from the file's.
Mobile sharing the largest regime Buttons were 58px tall on a 402px phone — the same as on a 1622 monitor, because base and 2xl both used px-6 py-4 and only the laptop band was compressed. Gave mobile its own step (50px). A three-regime scale where mobile inherits the widest is a bug waiting to be noticed on a phone.
Radius not responsive The featured card's radius-32 was flat at every width. Below xl every grid collapses to one column, so all ten cards are the same width and only one had bigger corners. rounded-radius-20 xl:rounded-radius-32. Found by Flore on her phone, not on the laptop.

Testing on a real phone

Three of the day's bugs — the oversized buttons, the card radius, and the crop reading as too aggressive — were all found by Flore looking at the site on her actual phone, not in a browser at 390px. Getting that working took a detour worth recording:

Two recurring localhost traps. (1) Vite silently moves to the next free port when 5173 is taken, so the remembered URL points at nothing while the server is alive one port over — the URL is whatever Vite prints, not what you remember. (2) The dev server binds to loopback only; a phone can't reach it without npm run dev -- --host, and you can't add that flag to a server that's already running. One terminal tab = one server; typing a new command into a busy tab feeds it to the running process, not to bash. That last one cost three exchanges.

What I'd do differently next time

Send the parent, not the part

When a new element is being placed rather than an existing one restyled, the containing frame's node id answers the only question that matters. A component id alone can't.

Keep test strings out of sampled frames

Placeholder text sized two row heights that then got imported as layout constants. If a frame is going to be built from, its content should be the real content or obviously-marked stand-ins.

Export artwork without its frame

Borders, stamps and rounded corners belong in CSS, where they can be resized and restyled. Baked into the asset they freeze the layout around them.

Say the goal, not the mechanism

"These should stay aligned however long the text is" would have got the right answer first time. "I added fillers" got a literal filler.

Shareable hook
Spent a day building my portfolio from my own Figma file and learned more about how I structure that file than about the design. The slowest moment wasn't a hard layout problem — it was a button that lived in a different page frame than the one I was reading, so its coordinates looked plausible somewhere it didn't belong. The fix is one habit: when you're placing something new, send the containing frame, not the component. A component id tells you what a thing looks like; only the parent tells you where it goes.
