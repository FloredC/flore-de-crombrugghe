## 1. Deploy and domain

Every push to `main` deploys via `.github/workflows/deploy.yml` (GitHub Pages).

The site is served from `floredecrombrugghe.com` at the root. **Four things must
agree:**

1. `BASE` in `vite.config.js` (`'/'`)
2. The router `basename`, which reads it back
3. `pathSegmentsToKeep` in `public/404.html` (`0`)
4. `public/CNAME`. **Delete it and the domain silently detaches.**

The domain is also written out in full in the `og:*` tags of `index.html` and in
`ORIGIN` in `scripts/prerender.mjs`. Changing the domain means editing all of them.

DNS lives at Squarespace, not GitHub.

**Deep links:** `public/404.html` plus a script in `index.html` restore unknown
paths before React Router starts. Project routes are real files since
prerendering, so the shim only catches process logs, the renamed slug and typos.

**Asset paths from content** (frontmatter, case-study files) are invisible to
Vite and must go through `src/lib/assetUrl.js`. Harmless at base `/`, broken
the moment the site moves to a subpath.

**Test a deploy locally with `npm run preview:pages`.** It's the only setup that
behaves like Pages (404 fallback, `301` to trailing slash).

## 2. Link previews

`scripts/prerender.mjs` writes a real HTML file per project after the build.
It's the only thing that makes per-page link previews work: crawlers don't run
JavaScript.

**Adding a project:** one `.mdx` in `src/content/projects/` plus a 1200×630 image
at `public/images/link-previews/<slug>.png`. No script change. Missing image:
falls back to the homepage image with a build warning.

## 3. Analytics

GA4 `gtag` in `index.html` must stay **after** the history-restore script, or it
logs the encoded `/?/work/...` path. Known quirk: in-app navigation can be logged
under the previous page's title. The path is always right.

## 4. Tokens and type

Three files in `src/styles/tokens/`: primitives → semantic → components.

- **Colour:** components use the semantic layer only, never a primitive.
- **Spacing and radius are flat on purpose.** Tailwind maps straight onto the
  primitives. Don't add a semantic spacing layer: `24` is 24 in every theme.
- **Type sizes** are generated by `scripts/type-scale.mjs`. Edit its anchors and
  paste the output into `tailwind.config.js`. Never hand-edit a `clamp()`: it
  silently moves the Figma-measured ends.

## 5. Content

All copy lives in `src/content/`, loaded by `src/lib/content.js`.

| File | Drives |
|---|---|
| `projects/<slug>.mdx` | Homepage card, link preview, prev/next order |
| `case-studies/<slug>.js` | The project page itself |
| `sections/<name>.mdx` | Work, Approach, About, Contact |
| `hero-map-hotspots.json` | The nine map markers |

- **The `.mdx` body text is never shown.** It's a fallback for slugs without a
  case-study file, which is none. Edit the `.js` file instead.
- `wip: true` in frontmatter keeps a page out of other pages' prev/next links.
- **Hotspot colour lives on the discipline** (`src/lib/disciplines.js`), never on
  a single hotspot. An unknown discipline throws on purpose.
- Artifakt's `processLogs` is one list shared by the log cards and the log route.
  Don't duplicate it.

## 6. Pages

- `ProjectPage.jsx` picks a layout by slug: full case study, Artifakt, snapshot,
  NDA or work in progress. **A layout that serves several slugs must never
  branch on slug.** Anything that varies comes from the case-study file.
- Process logs (`/work/:slug/process/:log`) show HTML files from
  `public/process/<slug>/` in an iframe.
- `/work/welcome-to-my-city` is the only redirect. If a second slug is renamed,
  collect redirects into a map instead of adding routes.

## 7. Components

- **One button component**, `ButtonLink.jsx`, with variants. Fix a state there
  once. `tertiary` and `menu` are the same treatment.
- **Icons** are SVG files in `src/assets/icons/`, imported through
  `vite-plugin-svgr`. `vite.config.js` rewrites Figma's baked-in fill colours to
  `currentColor`. If icons stop reacting to hover after a new export, a new
  colour is missing from that list. Never paste SVG markup into a component.
- **Map on phones** (`PanZoomContainer.jsx`): no zoom, wheel disabled, one-finger
  drag off. Each of these fixes a real bug; read the file's comments before
  changing any of them.
- **Wayfinding:** no `bubbleCopy` in a section file means no avatar and no bubble.

## 9. Layout

- **Where values live:** `src/lib/layout.js` (homepage) and
  `src/lib/caseStudyLayout.js` (project pages). Import from there, don't write
  spacing inline.
- **Figma has two frames only:** `402-mobile` and `bp-1622-desktop`. Every
  breakpoint in between is a judgment call.
- **Three size ranges:** phone/tablet, laptop (`xl`), large desktop (`2xl`,
  re-pointed to 1600). `xl:` without a `2xl:` partner means both agree on purpose.
- **Grids:** Work and the editorial sections use different column grids. Read
  them from the Figma frames; never infer them from card widths (this went wrong
  once, with identical pixels).
- **`Container` padding is a `clamp()`, not breakpoint steps.** Steps made the
  content narrower as the window got wider.
- **The hero fold chain** in `globals.css`: four variables decide how much room
  the map leaves for the Work heading. Change those, not the map size.
- **Map fit:** `Hero.jsx` fits the map to the measured artwork (`MAP_ART`), not
  the SVG box.
- **Above-the-fold changes:** measure with `npm run shoot`. It must use the
  Chrome DevTools protocol; `--window-size` screenshots lie about the fold.

## 10. Interaction and accessibility

- Map popovers (`Hotspot.jsx`): hover, tap or keyboard focus opens; a bridged
  hit area keeps them open on the way to the popover. One open at a time.
- **Tap targets are 44×44px**, made by an invisible button around the visible
  dot. The dot keeps its size.
- **Never scale the map with a CSS transform.** It shrinks the tap targets too.
- **Never mix an inline `style` shadow with a Tailwind focus ring.** The inline
  style wins and hides the ring. Use classes for both.
