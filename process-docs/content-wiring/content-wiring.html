2 Aug 2026 Content wiring: cards, captions, embeds Building with Claude

The plan was stage 8 of the build order — swap placeholder copy for real copy before doing any type or layout pass. What actually happened: two rounds of me and Claude meaning different things by "content wiring," a detour through where image files live, and a chart version mix-up. The content did land, but the useful material here is the friction, not the result.

The main misunderstanding — and the part that wasn't a misunderstanding

Claude reported content wiring as basically done. From my side almost nothing that mattered had been added, and I had to ask twice before the real copy got pulled. Two separate things were going on, and only the first is a vocabulary problem.

My definition

Content wiring = the media (images, iframes, embeds) + the actual written content. Now the agreed definition.

Claude's working definition

"Every field that exists in the content model holds a non-placeholder value." Narrower, and never said out loud so I could disagree with it.

The real failure

It didn't even meet its own definition. Four cards still read "Placeholder one-line hook for the work grid card" and the other six had one-line stubs that just restated the title — while Figma had 2–3 sentence descriptions for all ten, from the start.

The moment that actually explains the session. At the very start, Claude grepped the content files, found those four literal Placeholder descriptions, listed them to me — and then asked whether I would supply the copy or whether it should draft some, offering to use my writing-voice skill. It offered to write copy that already existed in the Figma file it had been reading all session. The wrong assumption wasn't about the word "content"; it was treating missing content as not yet written rather than not yet pulled. Default should be the opposite: assume the content exists in Figma and go look, before ever asking me to write anything.
Turning point
Define "content wiring" as: frontmatter + card captions + body prose, listed explicitly
Claude marked the stage as done twice while six case-study bodies were still literally "Placeholder case-study body…". Asking for a full placeholder audit (a grep for PLACEHOLDER across src/content/) surfaced the real remaining list in seconds — that should have been the first move of the stage, not a recovery step.
Turning point
Image labels are a real component element, not alt text
I said "the images have labels." Claude assumed I meant screen-reader alt text and asked which I wanted. The answer was neither guess: every ProjectMedia in Figma contains a visible caption inside the bordered frame ("Cost calculator — production web app"). The built component had no caption element at all — not empty, not placeholder, absent since the Skeleton stage. That's why no placeholder audit could have caught it: a field missing from the content model can't be found by searching for unfilled fields. The card also gave no visual tell, since the thumbnail, title, description and button were all real.
Content model
Replace tags: [...] with a single meta: "..." string
Figma renders one grey line ("AI • Vibecoding"), not separate tag chips. Keeping an array meant the component had to invent the separator. Making it one pre-joined string puts that punctuation back in my control as content.
Interaction
Podcast hotspot anchor-scrolls to its card instead of opening Spotify in a new tab
CLAUDE.md said the podcast hotspot had "no card to scroll to" so it should link out. That stopped being true once the Approach MediaCards existed. Label changed to "to podcast". The spec doc is now stale on this point.
Embed
Language River self-hosted in public/, iframe measures its own height
Removes the external-hosting blocker entirely (build order stage 7 is now closed). The chart's height is content-driven and changes with width — 371px on desktop, 387px on mobile when the legend rewraps — so a fixed height clipped it on phones and Figma's aspect-ratio box left dead space on desktop. Because it's served same-origin, the parent can read the chart's real content height directly, with no edit to the generated HTML file.

Where the time actually went

Asset location

I upload images to the GitHub repo root on main. Claude was checking only the local working tree and the feature branch, concluded a file didn't exist, and asked me for it three times. It was already committed.

Pasting images in chat

I re-sent screenshots twice thinking that delivered the files. It doesn't — pasted images arrive as pixels, not as files on disk that can be committed. Worth knowing so I don't repeat it.

A filename that lied

img-friends-of-figma-read-the-room.png was the Speak the Room photo, already in the repo. Claude ruled it out by reading the filename instead of opening the file, so we both hunted for a missing asset that wasn't missing.

Chart version mix-up

I pointed at …-framer-previous.html from an archive folder. A checksum showed the file already in public/ was byte-identical to its sibling …-framer.html — I'd clicked one row off. I still chose the older one after seeing the diff.

Figma hygiene — four cards carry unedited component defaults. Artifakt's caption, PitchPivot's caption, and Rega's both meta and caption still hold the ProjectCard component's default text (Sinomocene's caption and "Dataviz • NatGeo"). Rather than ship visibly wrong copy or silently invent replacements, these render on the page as REVIEW — … markers. Same class of problem as the duplicate-frame issue earlier in this build: an instance that was never overridden looks exactly like real content when read through the API.

Technical difficulties

Card anchors landed under the sticky nav scroll-margin-top was scoped to section[id] only, so every project-card anchor was affected — a latent bug, not new. Extended to article[id].

What I'd do differently next time

Rule
Assume the content exists in Figma. Look before asking me to write anything.
The single highest-value change. Every time Claude hit missing copy it read that as "Flore hasn't written this yet" and asked me to supply or approve drafted text. The correct reading was "I haven't pulled this yet." Asking me to write copy that already exists is worse than useless — it burns a round trip and risks inventing a second, competing version of my own words.
Rule
Diff the Figma component's layers against the content model — in that direction
Mapping Figma onto the fields that already exist can only ever find values for fields someone already thought of. Asked the other way — "what layers does this component have that my model has no field for?" — meta, the image caption, and the ValueCard image block all surface in one pull. This is the same rule as enumerating a component's full variant/state matrix before building it, applied to content instead of states.
Process
A placeholder grep is a starting point, never a completeness check
Searching the content files for the word "Placeholder" only matches text inside fields that already exist. A slot that was never modelled has no line to match, so it stays invisible while fake-but-filled values are loud. It reported "four items left" while three whole slots were missing and six descriptions were stubs.
Process
Don't trust a "stage done" line in CLAUDE.md over the Figma file
A status note reading "all project frontmatter is real" is why the ProjectCard nodes were never pulled in the first round at all. The doc described an earlier session's intent; the file is the truth.
Process
Say where a file is, not that I sent it
"It's on GitHub, on main, at the repo root" is instantly actionable. "I sent it" cost three rounds because chat images aren't files.
Figma
Sweep instances for unedited defaults before a content pull
Four of ten cards had leftover component defaults that read as plausible real copy through the API. The instance-naming convention (ProjectCard — Rega) makes instances easy to find; it doesn't tell you whether their content was ever overridden.
Shareable hook
Claude found four cards on my site still reading "Placeholder one-line hook" — and asked whether I'd like to write the real copy, or have it drafted for me. The copy already existed. It had been sitting in the Figma file Claude had been reading all afternoon. It hadn't misread the content; it had never occurred to it to go and get it, because missing text reads as not yet written when it almost always means not yet pulled. The lesson I'm keeping: when an AI collaborator offers to write something for you, check whether you've already written it.
3 Aug 2026 Reading the log back: two words doing too much work Building with Claude

Went back over yesterday's entry the next morning and kept not understanding my own process doc. Both times the sticking point was a word, not a fact — "placeholder" and "frontmatter" were each covering several different things, in a doc I'd have to re-read in six months. Worth its own entry because the fix is vocabulary, and vocabulary is the part that quietly decides whether a status report means anything.

"Placeholder" was doing three jobs

WhatWhere it livesWho made itWhat it means
[ img ] in a dashed box Figma Me A deliberate design convention: this image slot is real, the asset is pending.
"Placeholder one-line hook for the work grid card." description: in the MDX files An earlier Claude session Stand-in text so the card had something to render while layout got built. Now called scaffolding text, to stop it colliding with mine.
Dashed "Image placeholder" boxes MediaCard.jsx Claude, this session Stand-in UI where no image had been wired yet.
When Claude said "placeholder audit" it meant only the middle row. I heard the top row. We each had a coherent picture and they weren't the same picture — which is exactly the shape of the bigger misunderstanding a day earlier, just smaller and easier to see.

"All project frontmatter is real" — the status line that caused the miss

This sentence sat in CLAUDE.md as the recorded state of the content stage. Claude read it, believed it, and therefore never pulled the ProjectCard nodes in the first round. It's worth unpicking because it's wrong in an instructive way. 

description: "Placeholder one-line hook for the work grid card."
└─ field ─┘  └────────────── scaffolding text ─────────────────┘

description: "2018 — 200+ icons, one grammar — pharma science communication…"
└─ field ─┘  └────────────── my actual words ─────────────────────────────┘

Frontmatter is the block of labelled lines at the top of each .mdx file, between two --- markers; the prose underneath is the body. So the claim meant: on every project file, every one of those lines holds my words rather than a stand-in.

It was false

Four description: fields still held scaffolding text — written by a previous Claude session, in the very commit that set up the content model.

It was also meaningless

Even where true, it describes internal code fields. It says nothing about body prose, and nothing about a slot like imageCaption that was never a line in the file — so the claim sails straight past it.

It sounded finished

"Is real" reads as a completeness claim. It isn't one. That's what made it dangerous rather than merely unhelpful.

Rule
Status notes describe what a visitor sees — never which code fields are populated
"All project frontmatter is real" is unfalsifiable from my side; I can't see frontmatter. "Titles and CTAs real; descriptions still scaffolding on 4 of 10, stubs on the other 6; image captions not built; case-study bodies all scaffolding" is something I can check against the actual page in ten seconds. Rewritten in CLAUDE.md in that form.
Rule
Name the author of a placeholder when reporting one
"Four cards still have scaffolding text an earlier session wrote" points at the fix. "Four cards have placeholders" sounds like I owe someone copy — which is precisely the wrong conclusion that cost two rounds yesterday.
Built
Restored the missing image placeholders, using my Figma convention done
Filling in real content had made pending images vanish rather than stand out — an item.image && guard meant Cold Plunge rendered nothing at all. Now a shared ImagePlaceholder renders the dashed [ img ] box. Pulling the ValueCard node to check its size surfaced a fourth missing slot: the ValueCard has an image block in Figma that had never been built either.
The pattern across both days. Every miss traced back to a claim that was true in one frame and false in another, with nobody naming the frame: "content wiring is done", "all frontmatter is real", "the images have labels", "I sent them". None were lies and none were understood. The cheap fix is describing things in terms of the artefact we both look at — the page, the Figma node — rather than in terms of whichever internal structure each of us happens to be holding.
Shareable hook
The status note in my project file said "all project frontmatter is real." It was wrong — but the more useful discovery is that it couldn't have been useful even if it were right: it described which code fields were populated, something I can't see and can't check. Every misunderstanding in this build traced back to the same shape — a sentence that was true in one person's frame and false in the other's, with nobody naming the frame. Now the rule is that status gets written in terms of what a visitor sees on the page.
