Artifakt — Scaffold Generation & Contour Reduction

Companion to the prompting-process doc. This one covers the scaffold — the loose, open line drawing the user traces and completes. It records how we got from a too-detailed generated sketch to a clean outer silhouette, the experiments that decided the parameters, and the rebuild that lets the whole pipeline run in the browser on GitHub Pages with no server.

01 What the scaffold is & why we reduce it

The scaffold is the starting drawing Artifakt hands the user — it should suggest a subject without finishing it, leaving room to trace, deviate, and complete. A raw generated sketch carries far too much information: facial features, interior anatomy, hatching, costume detail. That over-determines the drawing and removes the openness the tool is built around. The goal of contour reduction is to keep the gesture and silhouette and discard everything internal.

Silhouette / long contours

The outer boundary and main pose. These carry the gesture — we keep them.

Interior detail / short contours

Face, muscles, hatching, costume. These finish the drawing for the user — we drop them.

The dial

How much to keep is a single fraction. Too high = a finished illustration. Too low = an unreadable blob.

03 Art-vocabulary prompting abandoned

Before touching the pipeline shape, the first attempt at openness was purely lexical: prompting flux/schnell with art-school vocabulary pulled from a life-drawing moodboard — "thumbnail sketch," "gesture drawing," "construction lines," "30-second life drawing," "unfinished forms." The assumption was that this language would push the model to generate images at an earlier stage of the drawing process — the loose, under-built look of an actual construction sketch.

It didn't work that way. The model reads this vocabulary as a visual style, not a structural state. Outputs were still complete, anatomically resolved subjects — just rendered with sketch-like linework on top. A "gesture drawing of a horse" came back as a fully-formed horse with loose-looking lines, not an actual early-stage gesture with open, ambiguous form.

What we wanted

A structural state: an incomplete drawing, genuinely under-determined, the way a human's hand lands a few seconds into a sketch.

What we got

A style: a finished, fully-resolved subject wearing sketch-like rendering — confident lines, but nothing actually left open.

The lesson

Diffusion models don't have a notion of "stage of completion" to prompt toward. "Unfinished" is description, not a lever.

Moodboard source — life-drawing construction sheet (loose sketch → refine → refine → define; staged figure/gesture studies) used as the basis for the abandoned art-vocabulary prompts.
Takeaway: stop trying to prompt incompleteness. The model can't be talked into leaving things out — it always resolves the subject. Reframe from "generate an unfinished drawing" to "generate a finished drawing, then selectively discard information." This is the shift that leads directly to the contour-reduction approach in Section 05 — detail has to be removed structurally (geometry/segmentation), not stylistically (prompt wording).
04 Experiment 005 — img2img from an SVG motif abandoned

First attempt at openness: seed an abstract SVG motif and run flux/dev/image-to-image at varying strengths, hoping the model would "loosen" it into a sketch. It didn't. Even at low strength the output read as a finished, shaded illustration with a background — the opposite of an open scaffold. This is also the experiment that burned most of the fal.ai credit (1,628 megapixels), so it's a cost lesson too.

07 From OpenCV to the browser shipped

The experiments ran in Python with OpenCV behind a local proxy. But Artifakt has to run publicly on GitHub Pages — a static host with no backend: no localhost, no proxy, no Python, no OpenCV. So the entire reduction pipeline was rebuilt in browser-side JavaScript on a Canvas, reproducing the exact OpenCV behaviour, including the RETR_EXTERNAL "outer boundary only" result.

1 · Grayscale

Read Canvas pixels, weighted luma.

2 · Gaussian blur

Separable 3×3 kernel, matches cv2.GaussianBlur(3,3).

3 · Canny

Sobel gradients → non-max suppression → double-threshold hysteresis (20/60).

4 · Close gaps

Binary dilation (radius 5) so the outline is continuous.

5 · Flood-fill BG

Fill from the borders; whatever it can't reach is the figure.

6 · Erode + trace

Undo the dilation, then draw only figure pixels touching the background = outer silhouette.

Why flood-fill instead of "keep top N contours"? Earlier JS attempts kept every Canny edge pixel, so interior lines (mane, muscles, costume) survived — the bug the user kept seeing. RETR_EXTERNAL in OpenCV only traces the outer boundary of a filled region. The flood-fill reproduces that: background is reachable from the edges, the figure is the unreachable interior, and we trace just its rim.
