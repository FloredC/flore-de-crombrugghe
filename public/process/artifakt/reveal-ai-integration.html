Phase 0 Baseline — Canvas Simulation (no AI) Starting Point
ToolHTML Canvas API (code-drawn)
Cost$0
SpeedInstant

Before any AI was added, the app used algorithmically drawn canvas simulations for each artist — botanical lines for Merian, spirals for Bourgeois, etc. Beautiful but not transformative. The user's sketch was overlaid on a pre-drawn motif, not reinterpreted.

Why it wasn't enough: The output looked generated, not personal. The sketch didn't influence the style — it was just a trace on top of a generic motif.
Canvas simulation — Merian botanical style. Instantly generated, always the same regardless of sketch.
Result: Beautiful but generic. Sketch had no influence on output. Not a "reveal."
Phase 1 Replicate + ControlNet Hough — Wrong Model No Change
ToolReplicate API · jagilley/controlnet-hough
Cost$10 credits (wasted)
Speed~30 seconds

First AI integration attempt. Used model version 854e8727... which turned out to be controlnet-hough — a model designed for detecting geometric lines in architectural photos. Completely wrong for hand-drawn sketches.

Why it looked the same: The Hough Lines model traces straight geometric lines and outputs them nearly unchanged. It doesn't apply artistic style. Also blocked by CORS — required building a Python proxy server to forward API calls.
Output: cleaned-up sketch. No style applied. Looks identical to input.
Debug view showing the Replicate output — sketch-like, no transformation.
Result: Identical to sketch input. $10 spent with zero visual improvement.
Phase 2 Replicate + ControlNet Scribble — Right Model, Wrong Results Marginally Different
ToolReplicate API · jagilley/controlnet-scribble
CostReplicate credits
Speed~30 seconds
Strengthconditioning_scale: 0.45

Switched to the correct scribble model (version 435061a1...). ControlNet Scribble is designed for hand-drawn input. But its core design is to preserve your sketch structure — it adds minimal style on top rather than transforming the image.

Why it still looked like a sketch: ControlNet Scribble is the wrong tool for a "reveal" effect. It's built for keeping your lines and adding texture — not for dramatically reimagining the image in an artist's style.

Phase 3 fal.ai + Flux Dev img2img — First Wow (strength 0.85) Major Breakthrough
Toolfal.ai · fal-ai/flux/dev/image-to-image
Cost~$0.025/image
Speed5–8 seconds
Strength0.85 (model ignores 85% of sketch)

Complete switch to fal.ai and Flux — a next-generation model. No proxy needed (CORS-friendly). At strength 0.85, the model discards most of the sketch and generates a new image guided primarily by the artist prompt. The results were dramatically different from anything before.

Why it suddenly worked: Flux is a fundamentally more powerful model than SD 1.5-based ControlNet. It understands artist names deeply and generates in their actual visual language. The sketch at 0.85 strength serves as a thematic prompt, not a compositional guide.
⭐ Bourgeois — Flux generated her iconic spider. Unmistakable.
⭐ Kusama — colourful scattered dots following sketch curve. Very her.
⭐ Merian — crescent shape with botanical decoration. Striking.
Result: First genuine "wow." Artist styles clearly recognisable. Problem: sketch composition completely ignored — model treats the word/theme as input, not the drawing.

Phase 9 Canny ControlNet — Neon Tube Artifact Wrong Tool
Toolfal.ai · flux-pro/v1/canny
InputSketch uploaded to fal storage as control image

Switched to Canny ControlNet: sketch edges used as structural guide, artist style from prompt only. Sketch composition was respected — but canny edge detection caused the model to render every line as a glowing neon tube. All artists looked like neon-light installations regardless of prompt.

Why it failed: Canny treats sketch edges as bright hard edges to render literally. The model's default interpretation of "bright edge on dark background" = glowing neon tube. Artist prompts weren't strong enough to override this visual artifact.
Bourgeois — red neon tubes exactly following sketch. Composition correct, material completely wrong.
Walker (labeled "L. Krasner" — UI bug) — multicoloured neon. Artists indistinguishable from each other.
Result: Sketch preserved but all artists looked identical — neon light tubes. Wrong endpoint for this use case.
Phase 10 Back to img2img — Better Prompts, "Line Treatment" Approach Breakthrough
Toolfal.ai · flux/dev/image-to-image
Strength0.81
Key changeEvery prompt opens with "KEEP THE EXACT LINE COMPOSITION OF THE SKETCH" + describes what the lines become as a material

Returned to img2img with sketch as input. Rewrote all prompts using a new approach: instead of describing the artist's style generically, describe what the sketch's lines ARE MADE OF. "Lines rendered as thick crimson yarn on cream linen" works better than "Louise Bourgeois artwork." Added explicit composition-preservation rule at start of every prompt.

Key prompt insight: Describe the output in three layers: (1) what the lines become as a physical material, (2) what the background is, (3) what small artist motifs appear as additions along the lines — not replacement subjects. This prevented the model from generating "artist icon" (spider, Nana) and instead made it treat the sketch's lines.

Key Insight — The Core Tension

Every attempt so far has hit the same wall: sketch fidelity and style transformation are in direct conflict with img2img. High strength → beautiful style, no sketch. Low strength → sketch preserved, no style. The IP-Adapter approach (Phase 7) sidesteps this by separating the two concerns — style comes from a reference image, composition comes from the prompt.

Phase 12 "Artist Icon" Problem — Higher Strength Loses the Sketch Diagnosis
Strength0.84 → 0.85
ProblemModel generates artist's most iconic imagery, abandons the sketch

As prompts improved and strength increased, a new problem emerged: the model stopped transforming the sketch and started generating each artist's most famous imagery instead. Bourgeois = spider (no sketch). Walker = narrative scene (no sketch). Saint Phalle = Nana figure (no sketch). Artistically strong, but the product promise was broken.

The core distinction

The model was doing sketch → artist icon instead of sketch → artist treatment.

The transformation rule should be: the artist applies their visual language to the sketch's lines — not: the artist generates their most famous imagery inspired by the keyword.

The sketch must remain the structural backbone. Artist motifs (spider, Nana, figures) should be additions along the lines, not replacement subjects.

Strength 0.85 — Mehretu grid, Bourgeois spider, Walker landscape, Saint Phalle outline, Mehretu again. All recognizable as artists. None connected to the sketch.
Result: Artistically strong but the user's sketch had disappeared. Pivoted: every prompt now opens with "KEEP THE EXACT LINE COMPOSITION OF THE SKETCH" + describes the transformation of lines specifically.
