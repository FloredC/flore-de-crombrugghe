## 1. Deploy and domain

Every push to `main` builds and publishes through `.github/workflows/deploy.yml`
(GitHub Pages, "GitHub Actions" source). No `gh-pages` branch, no build output
in the repo.

The site is served from `floredecrombrugghe.com`, at the domain root. Four
things have to agree:

1. `BASE` in `vite.config.js`: `'/'`.
2. The router's `basename`, which reads it back via `import.meta.env.BASE_URL`.
3. `pathSegmentsToKeep` in `public/404.html`: `0`.
4. `public/CNAME`: the domain itself. Pages reads it on every deploy.
   **Delete it and the domain silently detaches** while the other three still
   say root.

The domain is also written out in full in the `og:*` tags of `index.html` and
in `ORIGIN` in `scripts/prerender.mjs`, because link crawlers don't resolve
relative paths. Changing the domain means editing all of these.

DNS lives at Squarespace, not GitHub: apex `A` records to GitHub Pages, `www`
as a `CNAME` to `floredc.github.io`.

**Deep links.** Pages only serves files that exist. `public/404.html` turns an
unknown path into a query string, and a small script in `index.html` restores
it with `history.replaceState` before React Router starts. Since prerendering
(section 2), the ten project routes are real files, so the shim only catches
process logs, the renamed slug and typos.

**Asset paths from content.** Paths that arrive as plain strings (MDX
frontmatter, case-study files) are invisible to Vite. They go through
`src/lib/assetUrl.js`. With the base at `/` this changes nothing today, but it
matters again the moment the site is served from a subpath.

**Testing a deploy locally:** `npm run preview:pages` builds and serves `dist`
the way Pages does, including the 404 fallback and the `301` from
`/work/slug` to `/work/slug/`. It's the only local setup that catches
deploy-shaped bugs.

## 2. Link previews

`scripts/prerender.mjs` runs after `vite build` and writes one real
`dist/work/<slug>/index.html` per project, with its own title, description and
`og:image`. This is the only thing that makes per-page link previews work:
crawlers don't run JavaScript, so tags set from React are never seen.

Titles and descriptions come from the project `.mdx` frontmatter. **Adding a
project needs no change to the script:** add the `.mdx` and a 1200×630 image at
`public/images/link-previews/<slug>.png`. A missing image falls back to the
homepage image, and the build logs a warning naming the slug.

## 3. Analytics setup

GA4, plain `gtag` in `index.html`, placed **after** the history-restore script.
Earlier, it would log the encoded `/?/work/...` form as the page path.

In-app page changes are counted by GA4's Enhanced Measurement, not a manual
`page_view`. Known cost: the event can fire before React sets the new
`document.title`, so an in-app navigation may be logged under the previous
page's title. The path is always right. `DocumentTitle` in `App.jsx` keeps the
browser tab title in step.

## 4. Design tokens

Exported from Figma as three CSS files in `src/styles/tokens/`, imported in
this order by `src/styles/globals.css`:

- `primitives.css`: raw values (colour scales, 29 spacing steps, radius scale).
- `semantic.css`: role-based **colours only** (text, border, chart, action,
  surface, focus ring), pointing at primitives.
- `components.css`: component tokens (button variants and states, navbar),
  pointing at semantic tokens.

**Colour:** Tailwind's `theme.extend.colors` points at the semantic layer.
Component code never uses a colour primitive directly.

**Spacing and radius are flat on purpose.** Tailwind maps `space-N` and
`radius-N` straight onto the `--spaces-N` and `--radius-N` primitives. A
semantic layer earns its place for colour, because a role can be re-pointed.
`24` is 24 in every theme, so an alias would only add a second name to keep in
sync.

**Type:** one typeface, HK Grotesk, self-hosted. Sizes are fluid `clamp()`
expressions in `tailwind.config.js`, generated by `scripts/type-scale.mjs`.
Edit the anchors in the script and paste its output; never hand-edit a clamp,
because that silently moves the Figma-measured ends.

## 5. Content model

All site copy lives in `src/content/`. Loaded by `src/lib/content.js`.

| File | Drives |
|---|---|
| `projects/<slug>.mdx` | The homepage card, the link preview, prev/next order. Frontmatter only in practice |
| `case-studies/<slug>.js` | The project page itself: blocks, media, captions |
| `sections/<name>.mdx` | Section-level copy for Work, Approach, About, Contact |
| `hero-map-hotspots.json` | The nine map markers |

**Project frontmatter** (every file has the same set): `title`, `slug`, `order`,
`status`, `meta`, `description`, `cta`, `externalLink`, `hotspotId`, `thumbnail`,
`breadcrumbZone`, `breadcrumbSubsection`, `breadcrumbBubbleCopy`, `featured`,
`imageCaption`. Optional: `wip: true` keeps a page out of other pages'
prev/next links.

The `.mdx` body text is a fallback only. It renders when a slug has no
case-study file, which today is never.

**Case-study files** export a default object with `slug` and `frame` (the
hero), plus layout-specific keys. The shape depends on the page layout
(section 6). Artifakt also exports `processLogs`, one list shared by the log
cards and the log route.

**Hotspot manifest:** each marker has `id`, `type` (`link` or `contact`),
`discipline`, `title`, `ctaLabel`, `target` (`project` slug or `anchor` href),
`x`/`y` as percentages of the map, and `markerSide`.

`discipline` is a key into `src/lib/disciplines.js`: `own-products`,
`client-work`, `selected-talks`, `outside-of-work`, `contact`. It decides the
popover label, marker dot, pulse and highlight colour together. Colour lives on
the discipline, never on a single hotspot. `getDiscipline()` throws on an
unknown key rather than falling back.

## 6. Pages and routes

Defined in `src/App.jsx`:

| Route | Page |
|---|---|
| `/` | `HomePage`: one scrolling page, sections Work, Approach, About, Contact |
| `/work/:slug` | `ProjectPage`, which picks a layout by slug |
| `/work/:slug/process/:log` | `ProcessLogPage`: a process log from `public/process/<slug>/` in an iframe, framed by the site nav |
| `/work/welcome-to-my-city` | Redirects to `/work/welcome-to-my-island` (the only renamed slug) |

**Page layouts**, mapped by slug in `src/pages/ProjectPage.jsx`:

| Layout | Component | Slugs |
|---|---|---|
| Full case study | `CaseStudy` | pitchpivot (also the default) |
| Artifakt | `CaseStudyArtifakt` | artifakt |
| Snapshot | `CaseStudySnapshot` | sinomocene, teamchatviz, roche |
| NDA | `CaseStudyNda` | rega, myride, trail-app, sbb |

A layout serving several slugs must never branch on slug. Anything that varies
arrives as data from the case-study file.

Every project page ends with the contact block, wired once in `ProjectPage`.

## 7. Components

Only what isn't obvious from reading the code.

**One button component.** `src/components/ButtonLink.jsx`, with a `variant` prop
(`primary`, `secondary`, `tertiary`, `menu`, `popover`). Every button on the
site renders through it, so a state is fixed once. `tertiary` and `menu` are
the same treatment under two names. `SECONDARY_BUTTON_CLASS` is exported so
`ContactEmailButton` (a real `<button>`) matches without copying styles.

**Tag follows behaviour, not looks.** Anything that navigates is an `<a>`,
whatever it looks like. `<button>` is only for actions without navigation: the
copy-to-clipboard controls (`CopyButton`, `ContactEmailButton`, both using
`src/lib/useCopyToClipboard.js`).

**Icons.** SVG files in `src/assets/icons/`, imported as components through
`vite-plugin-svgr` (see `icons.jsx`). `vite.config.js` rewrites the fill colours
Figma bakes into exports to `currentColor`, so icons follow hover and focus.
If icons stop reacting to state after a new export, that list of colours is
why. Never paste SVG markup into a component.

**Map on phones.** `PanZoomContainer.jsx` is used only on phones; above that the
map scales to fit. No zoom (`minScale` = `maxScale` = 1), wheel disabled (the
library's wheel handler blocks page scroll). On touch screens one-finger drag is
off and two-finger pan stays on. Re-centring uses a `ResizeObserver` on the
container, not a window resize listener.

**Nav** (`Nav.jsx`). Homepage: hidden until the hero leaves the screen, then
sticky; the current section is underlined via an `IntersectionObserver`.
Mobile: a pill that opens into a stacked menu. Subpages: "← Work" and Contact
only. The mobile/desktop switch is Tailwind `md`.

**Wayfinding** (`Wayfinding.jsx`, `DistrictBreadcrumb.jsx`). Avatar, speech
bubble and "You are here" line above sections. The avatar is picked from
`AVATAR_BY_VARIANT`; adding one is a line there plus a key in `HomePage`. No
`bubbleCopy` in the content file means no avatar and no bubble.

**Media tints.** `src/lib/mediaTints.js` holds the background tint behind each
project's artwork.

**Motion.** Scroll reveals: `src/lib/useReveal.js` and `Reveal.jsx` (content
stays visible if the browser can't observe scrolling). Chapter navigation:
`useChapterProgress.js`, `ChapterNav.jsx`. Illustrated moments: `Helicopter.jsx`,
`RegaFlypast.jsx`, `EyeAnimation.jsx` (Lottie). Reduced motion is handled in
`globals.css` for CSS animations and inside each JS animation
(`RegaFlypast`, `EyeAnimation`, `AvatarRega`, `ReadingProgress`).

## 9. Layout and density

**Where values live.** Homepage grids, gutters and section rhythm:
`src/lib/layout.js`. Case-study widths, spacing and media sizes:
`src/lib/caseStudyLayout.js`. Components import from there instead of writing
spacing inline. Each constant names the Figma node it was measured from.

**Figma frames.** Only two: `402-mobile` and `bp-1622-desktop`. Every
breakpoint in between is a judgment call.

**Three density ranges.** Phone/tablet, laptop (`xl`, 1280) and large desktop
(`2xl`, re-pointed to 1600 in `tailwind.config.js`). Read `xl:` as "from laptop
up" and `2xl:` as "back to the generous Figma value". An `xl:` without a `2xl:`
means both ranges deliberately agree. The featured card jumps from 4 to 5
columns at 1600; spans are whole numbers, so this can't be smoothed.

**Grids.** Work and the editorial sections (Approach, About) use two different
column grids on the same container. Read them from the Figma frames, never infer
them from card widths. The grids engage at `xl`; below, sections fall back to
plain N-up grids. Approach and About are hand-placed collages at `xl` and
collapse to a grid below.

**Container.** Padding is fluid (`clamp`), not stepped, so the content width can
never shrink as the window grows. Above the desktop frame, content and map stay
capped and the margins grow.

**Screen height matters more than width on laptops.** `ProjectMedia.jsx` and the
case-study `Media` cap media height with `svh` values, set so they never bite on
a tall window.

**Hero fold chain.** The map must leave the Work heading visible. The reserve is
calculated from four CSS variables in `globals.css` (block "THE HERO FOLD
CHAIN"): hero top padding, map-to-Work gap, Work heading height (measured at
runtime), clearance. `SECTION_PAD_WORK` reads the same gap variable, so the two
can't drift.

**Map fit.** `Hero.jsx` fits the map to the artwork measured with `getBBox()`
(`MAP_ART`), not to the SVG box, and shifts it right with `MAP_SHIFT_X`.

**Measuring above-the-fold changes.** `npm run shoot` drives headless Chrome
across six desktop sizes and writes a screenshot sheet plus `metrics.json` to
`screenshots/`. It has to use the Chrome DevTools protocol: the plain
`--window-size` flag lays the page out shorter than the screenshot, which hides
exactly what the tool is for.

## 10. Interaction and accessibility

**Map popovers** (`Hotspot.jsx`, `@floating-ui/react`):

- Mouse: hovering a marker opens its popover and lights its map highlight. A
  bridged hit area (`safePolygon`) keeps it open while moving towards it.
- Touch: tap opens, tap outside closes.
- Keyboard: markers are real `<button>`s. Focus or Enter opens, Escape closes.
- One popover at a time. Link variant: title plus CTA; project CTAs scroll to
  the matching Work card, others go to their own anchor or URL. Contact
  variant: title, email, copy button.

**Rules that apply everywhere:**

- Marker tap targets are 44×44px, made by an invisible button around the visible
  dot. The dot keeps its size.
- Never scale the map with a CSS transform: it shrinks the tap targets with the
  artwork.
- Never combine an inline `style` shadow with a Tailwind focus ring. Inline
  styles win and hide the ring. Use classes for both.
- Verify states in the browser (real Tab key, `getComputedStyle`), not by
  reading class names.
